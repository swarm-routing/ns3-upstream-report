Your line numbers match. One small correction: the periodic-update jitter is drawn at line 960 of `dsdv-routing-protocol.cc`, after the per-socket loop; line 969 is in `SetIpv4`. Your conclusion holds. DSDV draws no random number inside either send loop, so its dependence on heap layout is the order of the per-interface sends, not which socket receives which draw as in AODV.

The `NotifyRemoveAddress()` point is new to us, and we think it matters:

- In DSDV, the replacement socket created there is not bound with `BindToNetDevice()`. DSDV's own `NotifyInterfaceUp()` and `NotifyAddAddress()` do bind theirs, and so does AODV's `NotifyRemoveAddress()`. That looks like a separate inconsistency, which could be fixed in the same merge request.
- It also decides between the two fixes the report suggests. A map keyed by the interface index still works there, because `NotifyRemoveAddress()` is given the index `i`. A comparator on `GetBoundNetDevice()->GetIfIndex()` would not, because that socket has no bound device. So we would recommend keying by interface index for both AODV and DSDV, with the receive path told its interface index directly (for example, bound into the receive callback when the socket is created), since DSDV's receive sockets are bound to `Ipv4Address::GetAny()` and their address does not identify the interface.

Two things of ours that may help with the merge request:

- **A working version of the same change, in our own ns-3 module.** Our AntHocNet routing protocol had exactly these two maps and fixed them by ordering on the bound device's interface index. The comparator is at https://github.com/swarm-routing/AntHocNet/blob/3a3995ac598699ec5c39fca734b6b616247fa597/ns3/model/anthocnet-routing-protocol.cc#L1349, its declaration at https://github.com/swarm-routing/AntHocNet/blob/3a3995ac598699ec5c39fca734b6b616247fa597/ns3/model/anthocnet-routing-protocol.h#L274, and the whole change at https://github.com/swarm-routing/AntHocNet/pull/471. It taught us two lessons:
  - Once the comparator reads the socket's bound device, the socket must be erased from the map before `Close()`; see https://github.com/swarm-routing/AntHocNet/blob/3a3995ac598699ec5c39fca734b6b616247fa597/ns3/model/anthocnet-routing-protocol.cc#L714.
  - That comparator only works because every socket in our module is bound before it is inserted. An unbound socket, like DSDV's in `NotifyRemoveAddress()`, falls back to pointer order. This is one more reason to key by the interface index itself in AODV and DSDV.
- **A test that tells a good fix from a bad one.** `ArmIsolationTest` (https://github.com/swarm-routing/sim-tools/blob/bb2951e1d25eee3e5d5260927f6288a443fa4ee8/ns3/routing-bench/test/routing-bench-test-suite.cc) prints `DIFFERS` on `master` today and `matches` once the order no longer depends on the heap. In our scratch patch, with the AODV maps ordered by interface index, every heap-churn level gave the identical result: https://github.com/swarm-routing/sim-tools/issues/198#issuecomment-6896069314. How to run it is in the Reproduction section linked in our earlier reply.
