# aodv: hello timer is never restarted when an interface comes back up

**Modules:** aodv (`RoutingProtocol`: `NotifyInterfaceUp`, `NotifyInterfaceDown`, `NotifyAddAddress`, `NotifyRemoveAddress`, `HelloTimerExpire`, `DoInitialize`). **Version:** ns-3.49 and `master` (`8a06b457096e33ec072d13613001496de2569f0e`, 2026-11-23); `src/aodv/model/aodv-routing-protocol.cc` is byte-identical in both, so the line numbers below hold for both.

**Description.** When the last AODV interface of a node goes down, `NotifyInterfaceDown()` cancels the hello timer (`aodv-routing-protocol.cc:826-833`); `NotifyRemoveAddress()` does the same when the last AODV address goes (`:954-961`):

```cpp
    if (m_socketAddresses.empty())
    {
        NS_LOG_LOGIC("No aodv interfaces");
        m_htimer.Cancel();
        m_nb.Clear();
        m_routingTable.Clear();
        return;
    }
```

Nothing re-arms it. `NotifyInterfaceUp()` (`:721-786`) recreates the sockets, the broadcast route, the ARP cache and the wifi `DroppedMpdu` hook, the inverse of `NotifyInterfaceDown()`, but has no `m_htimer` call, and `NotifyAddAddress()` (`:838-895`) likewise. The timer is scheduled only in `DoInitialize()` (`:2325-2331`) and by its own expiry (`HelloTimerExpire()`, `:1945-1947`). So after all of a node's interfaces go down and come back up with `EnableHello=true`, the node never sends another HELLO for the rest of the run, while it goes on answering and forwarding route requests. Its neighbours lose HELLO-based link-break detection towards it (RFC 3561 section 6.9).

**Why it is not seen in ordinary runs.** At start-up the interfaces come up before `DoInitialize()` arms the timer, so the missing restart is invisible; only a down/up cycle on a running node shows it. None of the aodv tests (`src/aodv/test/`: `aodv-test-suite.cc`, `aodv-regression.cc`, `bug-772.cc`, `loopback.cc`, `aodv-id-cache-test-suite.cc`, ns-3.49) calls `SetDown` or `SetUp`.

**How to reproduce.** Three static nodes in a line 50 m apart, 802.11 ad hoc with ns-3's defaults (`YansWifiChannelHelper::Default()`), stock AODV with `EnableHello=true` (`HelloInterval` 1 s), stock ns-3 models only. At 10 s every non-loopback IPv4 interface of node 1 is set down (`Ipv4::SetDown`, so AODV gets `NotifyInterfaceDown`), at 15 s up again (`NotifyInterfaceUp`); the run ends at 30 s. A HELLO is counted on each node's `Ipv4L3Protocol` `Tx` trace (TTL 1, UDP port 654, an RREP with hop count 0 and dst = origin, as `SendHello` builds it). Default seed. The program prints the HELLOs per node and window, then `VERDICT reproduced` or `VERDICT not-reproduced`: https://github.com/swarm-routing/sim-tools/blob/f968693710a761cab6a99e05e16a3c8b63cc3867/docs/ns3-rcapa/aodv-hello-restart.cc

```bash
./ns3 configure -d debug --disable-werror --enable-modules="aodv;wifi;internet;mobility;applications"
curl -fsSL -o scratch/aodv-hello-restart.cc https://raw.githubusercontent.com/swarm-routing/sim-tools/f968693710a761cab6a99e05e16a3c8b63cc3867/docs/ns3-rcapa/aodv-hello-restart.cc
./ns3 build scratch/aodv-hello-restart
./ns3 run --no-build scratch/aodv-hello-restart
```

HELLOs sent per node, before (0-10 s) / down (10-15 s) / after (15-30 s):

| Build | node 0 | node 1 (restarted) | node 2 | Verdict |
|---|---|---|---|---|
| ns-3.49, stock | 10 / 5 / 15 | 10 / 0 / **0** | 10 / 5 / 15 | reproduced |
| `master` `8a06b457`, stock | 10 / 5 / 15 | 10 / 0 / **0** | 10 / 5 / 15 | reproduced |
| ns-3.49 with the patch below | 10 / 5 / 15 | 10 / 0 / **15** | 10 / 5 / 15 | not reproduced |
| `master` `8a06b457` with the patch | 10 / 5 / 15 | 10 / 0 / **15** | 10 / 5 / 15 | not reproduced |

Control, no restart (`--downAt=100 --upAt=100`): every node sends 30 HELLOs in 30 s, stock and patched, on both trees. Expected: node 1 sends about 15 HELLOs after 15 s, like its neighbours. Actual: none; it sent 10 before going down, so the timer worked until `NotifyInterfaceDown()` cancelled it.

**Root cause.** `aodv::RoutingProtocol` cancels `m_htimer` when it loses its last interface or address but has no matching restart when one returns; the only places that schedule the timer are `DoInitialize()` and the timer's own expiry.

**Proposed fix.** Re-arm `m_htimer` where AODV regains an interface or an address, when hellos are on and the timer is not running. The `IsInitialized()` guard keeps the start-up path unchanged: interfaces come up before `DoInitialize()`, which sets the timer's function and arms it itself, so a run without a restart takes the same path as before. **Suggested test.** A test under `src/aodv/test/` that takes one node's interfaces down and up on a running simulation and counts that node's HELLOs after the restart would fail today and keep it fixed; the reproducer above is a starting point.
